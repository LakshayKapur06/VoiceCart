# ADR-002: historical metadata discovery and bounded embedding profile

Continuation, 2026-11-02. Keep current-offer eligibility/cart authority unchanged. The selected real Amazon metadata has stale crawl-time USD prices and unknown inventory; filtering it exclusively through commerce qualification would hide all records. Add a labelled read-only metadata discovery route alongside the core commerce route, never an availability shortcut.

Exact/lexical metadata discovery now optionally uses the existing Ollama/pgvector adapter for exact dense scores. All configured hard brand/category/currency/price filters remain enforced. Ordering is lexical rank, exact semantic score and historical-price tie, explicitly uncalibrated; no new invented blended weights or relevance guarantee. The separate minimum is scoped to evaluated literal matches, not an unrelated low-price semantic candidate; global current minimum is always unverified for this route.

Long real descriptions can exceed compact encoder token windows. The opt-in serializer metadata-prefix-256utf8bytes-v1 supplies only a bounded UTF-8 prefix to the encoder while retaining full source/provenance and lexical documents. This is lossy derived-feature preprocessing, not truncated authoritative product facts. The default variant-text-v1 behavior is unchanged. Serializer/model/digest/dimensions/prefix are included in generation identity; changing profile requires explicit full reimport/re-embedding and matching query configuration. No same-shaped vectors are mixed. Actual semantic publication/query evidence is recorded separately from scripted tests and human relevance quality remains unmeasured.
