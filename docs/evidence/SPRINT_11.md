# Sprint 11 — customer shopping and accessible browser interface

Implemented actual same-origin customer HTML/CSS/JS, packaged assets and HTTP routes for session resume, search/details/provenance, configured local NLU, explicit list acknowledgement, cancel/repeat, native-browser PCM recording plus local ASR transcription review, local Piper response WAV, current-offer add and authoritative cart overview/target quantity/removal/retry. No browser cloud speech API is used. Historical unknown-stock records stay non-actionable. Decimal prices are converted to minor units with BigInt; backend money remains integer and JSON integers beyond JS safe precision are encoded as decimal strings.

New quantity/removal transactions use session/advisory locks and immutable receipts; UUID identity is guarded across add/adjust namespaces. Target quantity is revalidated against current facts when increasing. Replays return the committed receipt; no negative add receipt is fabricated. Session bootstrap resumes an existing valid capability instead of discarding the cart on reload. Uncertain operations retain their original IDs. Browser audio has stop/epoch fencing and half-duplex input/playback; explicit text/keyboard alternatives remain available.

173 source and 173 installed-wheel tests passed with isolated real PostgreSQL/HTTP, plus full compile/lint/format/types/Bandit/package/pip/advisory gates. Chromium 156 with Playwright 1.64.1 executed two customer system/accessibility tests: search→details→add→quantity→reload→remove, keyboard dialogs/shortcuts, 390px layout without horizontal overflow, and axe checks with zero violations in the checked state. Rendered 1440px/390px layouts were visually inspected. Browser fixture products exist only in the runner-owned disposable database, never in the real-data catalogue. Logs /tmp/voicecart-s11.log and /tmp/voicecart-browser-s11.log.

Physical microphone/speaker, actual screen-reader speech, mobile hardware and representative blind/low-vision acceptance remain Not Run. Automated axe/keyboard tests are not WCAG conformance or usability proof. Voice failure returns an explicit text alternative; no queued/synthesized WAV is claimed to have been heard. The actual model adapters remain separately verified by historical and continuation inference evidence; browser tests do not pretend to perform neural inference.
