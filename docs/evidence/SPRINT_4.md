# Sprint 4 — real catalogue authority and search

PostgreSQL/pgvector now has packaged checksum-verified migrations, empty metadata-only initialization, schema constraints, validated owner JSON import, atomic full-snapshot publication with previous-revision compare-and-set, source expiry, canonical aliases and consistent repeatable-read search. Embeddings are prepared before write locks; content serializer/generation fingerprints exclude volatile prices and stock. The local Ollama embedding endpoint validates count, dimension, finite normalized vectors and model identity. No automatic model download or catalogue seed occurs.

Exact identity remains case-sensitive. Structured cheapest selection evaluates the full source through the existing three-valued eligibility contract. An additional confirmed defect was fixed: active potentially matching products with no variant data previously disappeared from completeness checks. Unknown variant data now blocks a complete minimum/no-match; unrelated product categories do not. Parent membership uses one linear-time set construction.

Discovery uses actual PostgreSQL full-text and exact pgvector cosine queries in one snapshot. All hard predicates are rechecked. Lexical coverage precedes experimental title/semantic/price scoring; an irrelevant cheap accessory cannot displace a full literal match. Scoring v1's provisional .65/.25/.10 components and INR 100000-paise reference scale are implementation parameters, not measured optimal weights. Cheapest is separately scoped to evaluated literal-term matches, never asserted globally for subjective semantics. No neural reranker or ANN index is introduced.

Real-service tests use pgserver 0.1.4's disposable PostgreSQL 16.2/pgvector 0.6.2 through Unix sockets. This is test infrastructure, not an approved production server distribution; deploy a maintained, patched server/extension pair and rerun compatibility checks. Synthetic vectors test SQL/math, not encoder relevance. Tests cover migrations/no seeds, exact lookup, full-source minimum, source expiry, atomic rollback, stale job rejection, competing publishers, repeatable-read snapshots, vector generation mismatch, and empty imported source versus unpopulated catalogue.

`python scripts/verify.py --postgres --package` passed all 127 tests in the source and freshly installed wheel, plus compilation, lint/format, type, Bandit, dependency and diff checks. Packaged SQL assets were exercised from the installed wheel. A separate fresh application-schema database remained at zero products/variants before and after startup checks; all fabricated data lived exclusively in the guarded test database. No owner database was accessed.
