# Sprint 6 — runnable local search-to-cart and speech integration

Implemented the packaged `voicecart` / `python -m voicecart` entry point, explicit schema/import/status commands, deterministic search and operation-ID-based add/retry, plus an interactive nonvisual console. Natural-language requests use the real configured loopback Ollama adapter; no production mock or keyword-based general NLU fallback is installed. Current sessions accept each final once in PostgreSQL; late/cancelled responses are fenced. Only explicit eligible exact adds and complete structured cheapest requests can auto-dispatch; subjective best/cheapest or ambiguous variants ask for a choice.

The console has /listen, /end, /stop, /repeat, /ack, /retry ID, /cart and /quit controls. Text output is always available. Text-only lists require explicit acknowledgement after reading; actual response playback completion can acknowledge a list. Interrupted/error-fallback speech never silently publishes ordinal references. Session/offer/stock/receipt validation stays authoritative. Repeat never searches or mutates. No sample-data or checkout command exists.

Real optional adapters load SHA-256-verified local Whisper/Piper artifacts, capture bounded explicit microphone turns and queue/drain/abort actual sounddevice streams. No model is downloaded implicitly by application startup. All application success, clarification, ASR and template-error responses share ResponseSpeaker; cached recovery speech is optional and host-provisioned. A failed output uses the accessible text channel and reports unavailable delivery. Startup/control failures may be assistive-only. The older AudioPipelineSlice remains a contract/feasibility helper whose ASR/template errors are explicitly assistive-only; it is not the console's delivery implementation.

PortAudio completion is not proof that a user heard speech. The native output adapter returns no acoustic onset timestamp without calibration; under-1.5-second success is not inferred. Real microphone/speaker echo, permissions and human accessibility remain manual acceptance gates.

Automated gates: `python scripts/verify.py --postgres --package --audit` passed 155 source tests and 155 fresh installed-wheel tests, Ruff lint/format, configured source mypy, Bandit, compilation, dependency checks, diff checks and advisory audit (no known vulnerabilities in audited installed dependencies; editable local source is covered separately by source checks). System scenarios include real CLI subprocess search/add/replay, real PostgreSQL cart commits, scripted NLU through strict production validation, cancellation, malformed interpretation, empty/stale/no-match, unpresented references and template failure after commit. Scripted inference/device tests are not neural or hardware quality evidence.

Actual speech inference was also executed on Apple M1, 16 GiB, macOS 26.5.2: Piper 1.8.0 LJ medium generated two test utterances, explicitly resampled in memory to 16 kHz, and pywhispercpp 1.5.1 with CPU Whisper base.en transcribed them. Price/operator and negation survived these two smoke cases. Details and artifact identities are in MODEL_SMOKE.json. First combined model initialization took 17.687 seconds (including backend discovery/compilation); synthesis calls took 1.3145/0.2302 seconds and ASR calls 0.6147/0.6159 seconds. These are file-based stage timings, not microphone-to-audible latency, an accuracy benchmark or human comprehension acceptance. Reference Qwen provisioning/inference evidence is recorded separately when available; no scripted model response is passed off as real inference.

The independent fresh-schema probe remains empty of products and variants. Synthetic products only inhabit the guarded temporary test database.
