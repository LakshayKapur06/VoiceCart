# Security, privacy and deployment boundary

Customer sessions are random UUIDs inside HMAC-SHA256 signed, tenant/role/expiry-scoped HttpOnly SameSite=Strict cookies. Existing live sessions resume across page reloads; expiry is authoritative in PostgreSQL. Admin uses a separately provisioned high-entropy merchant credential, constant-time digest comparison and a 30-minute admin capability. API bearer admin credentials are for merchant servers/SDKs, never shipped in storefront JavaScript. No default production credential exists. Test credentials are explicitly TEST-ONLY in guarded drivers. Rotate the capability key to revoke all capabilities; logout clears the browser cookie but is not central revocation of a copied valid token. Production must use HTTPS/TLS termination with the fixed public origin, Secure cookies and private secrets management.

Host and Origin checks protect the same-origin browser API; no wildcard CORS exists. Mutating JSON endpoints require bounded bodies; authentication/authorization is enforced by the backend. Public session creation is rate limited. Requests are limited to 24 worker slots, 2 MiB JSON and connection/SQL deadlines. Saturation closes excess sockets rather than pretending success; clients must retain operation IDs. No public multi-user managed service is deployed or certified. Configure the public origin accurately behind a reverse proxy; forwarded headers are not implicitly trusted.

Each merchant requires a distinct PostgreSQL database. Registry IDs are bounded canonical names; duplicate databases fail startup. Catalogue, sessions, carts, receipts, import history and analytics are therefore physically separated by database, plus signed tenant capability checks. Local/native service clients default to loopback; deployment-only trusted hostname allowlists enable configured Compose service names. These are server settings, never request-supplied destinations. Avoid publicly exposed databases/inference. Parameterized SQL and strict parsing remain mandatory.

Application output is not authority. Cart writes use transaction/session locks, operation identity, current eligibility, atomic immutable receipts and new-connection verification. Quantity/removal has its own target-state receipt contract; operation IDs are protected across namespaces. Uncertain outcomes require the same operation/payload; repeat/stop do not undo commits or blindly dispatch a new add. Totals are current verified prices grouped by currency; unknown-price lines make totals incomplete. No stock reservation, checkout or merchant-platform transaction is implied.

Normal audio/transcripts are transient. Browser microphone capture is explicit and at most 30 seconds, with review before submission and text alternative. No browser cloud speech API is used. Recording/playback and late delivery are fenced. Browser sessionStorage retains only minimal unresolved operation metadata for the current session/tab; it is cleared on verified completion/session mismatch. Cookies and admin tokens are not stored in localStorage. External product images load only after an explicit checkbox, from the allowlisted image host, without a referrer. Public responses exclude raw video/user/source payloads.

Actual operational events contain only event kind, outcome/status, numeric duration and bounded stage timings, environment and timestamp. No raw query/transcript, credentials, IP, audio or arbitrary request path is stored. Popular-query analytics are therefore deliberately unavailable; checkout conversion is unmeasured. Test/development/merchant event environments are explicit, and disposable test databases never feed real merchant dashboards. Events expire after a configured 1–30 days (default 7); periodic server cleanup also clears expired DB sessions and cached response/turn context. Logical deletion does not securely erase WAL/backups. Owner must approve and operate backup/retention/secure-erasure policies.

Telemetry writes occur after the business response and cannot turn a committed cart receipt into a failed mutation. Failures increment an observed health counter. Admin publication is all-or-nothing full-snapshot CAS; duplicate/invalid/stale input fails, and applied migration checksums are immutable. Explicit source expiry and freshness are retained; editing historical metadata does not automatically make prices current. JSON import/export is supported; CSV is not implemented or exposed. HTTP imports are 2 MiB; larger sources use the CLI's validated file limit. Secrets, model binaries, catalogue rows, recordings and generated artifacts are ignored and excluded from container build context.

Release gates: maintained server/runtime patches; TLS/private network and secret-file ownership in actual Docker platform; real backup/restore and recovery drills on the deployment; target-device model capacity; representative accessibility evaluation; license/distribution decisions. Automated security tests and dependency scans are evidence, not penetration-test certification.
