# Transaction, catalogue and concurrency validation — 3 November 2026

Two additional fixes preserve existing architecture: after catalogue/row waits, add and target-quantity paths recheck session expiry immediately before mutation; a fresh adjustment-receipt lookup failure after commit raises explicit OutcomeUnknown instead of leaking a raw database exception. OutcomeUnknown requires original-ID reconciliation and is never success or permission for a new add. A committed receipt remains authoritative even if a response was lost.

[Targeted25-test execution](evidence/20261103_S20_transactions_verified/RUN.json) combines seven new real-SQL cases, sixteen existing cart cases and two merchant cases. Covers simultaneous target quantities, same-ID replay/altered payload, precommit rollback, postcommit loss/reconciliation, fresh receipt outage/restart-style new service recovery, session expiry between initial authorization and mutation (controlled clock with actual SQL rollback), and upstream deactivation after search. Existing tests cover add duplicate-worker concurrency, revision/stock/price changes, cancelled/conflicting turns, unavailable/prepared state and dump/restore. The initial expiry test expected the internal SessionError rather than the existing normalized CartError; inspected/corrected to assert exact invalid_or_expired_operation, no validation weakened. Both runs retained.
