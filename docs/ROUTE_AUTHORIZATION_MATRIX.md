# Route authorization and security matrix — 3 November 2026

Generated by inspection of server.py, web_api.py, admin.py and merchant_api.py; negative route cases are executed in `tests.test_security_extended.ExtendedSecurityTests.test_every_protected_route_requires_correct_role`. Positive supported flows are existing customer/admin/merchant Python, browser and Node integration tests. No third-party penetration certification.

Every route enforces exact configured Host; provided Origin must equal the fixed public origin. SameSiteStrict capability cookies plus JSON content-type/body constraints/no CORS protect browser mutations; Origin absence is accepted for server-side clients, not an authentication bypass. GET/POST/PUT are dispatched; other unsupported HTTP verbs get the standard handler response. Remote TLS is a deployment requirement, not supplied by this local server.

Different tenant/role signatures fail; the same bare session UUID is not sufficient for HTTP customer access. Administrator bearer is privileged and must stay out of browser bundles. Per-merchant databases/configuration and existing two-DB tests enforce isolation. Logout clears the cookie only; signing-key rotation revokes all copied capabilities, DB expiry is authoritative for customer sessions. Granular central revocation is not implemented and is an operator/product decision.
